# Alexey Korobko — Portfolio

Интерактивное персональное портфолио. Next.js 15 (App Router) + TypeScript + CSS Modules.
3D — Three.js / React Three Fiber (подключается на Milestone B).

**Текущий статус: финализация — SEO и подготовка к деплою завершены.**

---

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production-сборка
npm start        # запуск собранного
npm run typecheck
```

Нужен Node.js 20+.

## Что где менять

Весь редактируемый контент лежит в `content/`. Компоненты трогать не нужно.

| Что | Файл |
|---|---|
| Имя, роль | `content/profile.ts` → `name`, `role` |
| Тексты первого экрана | `content/profile.ts` → `hero` |
| Текст «About me», портрет, направления | `content/profile.ts` → `about` |
| Строка о доступности в футере | `content/profile.ts` → `footer.availability` |
| Email, Telegram, Instagram, локация | `content/contact.ts` → `channels` |
| Title, description, домен | `content/profile.ts` → `seo` |
| Проекты и кейсы | `content/projects.ts` |
| Таймлайн опыта | `content/experience.ts` |
| Раздел «What I do» | `content/services.ts` |
| Пункты навигации | `content/navigation.ts` |

### Контакты

`content/contact.ts`. У каждого канала три поля:

```ts
{ label: 'Email', value: 'hello@example.com', href: 'mailto:hello@example.com' }
```

Пока `href: null`, канал показывается текстом и **не** становится ссылкой —
битых ссылок на сайте не появится. Как только подставите реальный адрес,
канал автоматически появится ещё и в меню, и в футере.

### Раздел About

`content/profile.ts` → `about`:

- `intro` — короткое вступление;
- `body` — массив абзацев, каждый элемент = абзац;
- `areas` — направления работы (заменяют шкалы навыков);
- `facts` — необязательные цифры. Пока массив пуст, блок **не рендерится**.
  Формат: `{ value: '12', label: 'Projects shipped' }`. Непроверяемых
  «50+ клиентов» здесь по умолчанию нет и появляться не должно.

### Добавить проект

1. Скопируйте объект в массиве `content/projects.ts`.
2. Поменяйте `slug` (он же адрес страницы) и `order`.
3. Положите изображения в `public/projects/<slug>/` и укажите пути
   в `coverImage`, `heroImage`, `gallery`.

Готово. Карточка в витрине, страница `/projects/<slug>`, навигация PREV/NEXT
и метаданные соберутся сами — компоненты трогать не нужно.

Композиция карточек чередуется автоматически (`overlay` / `split`), чтобы
витрина не читалась как повтор одного шаблона.

| Поле | Поведение |
|---|---|
| `websiteUrl: null` | вместо ссылки — видимый плейсхолдер `[PROJECT WEBSITE URL]` |
| `published: false` | проект исчезает отовсюду, включая генерацию страниц |
| `gallery: []` | блок галереи не рендерится |
| `client: null` | строка «Client» в мета-панели скрыта |

### Главы кейса

`caseStudy` — массив глав. Порядок в массиве = порядок на странице.

```ts
{ key: 'idea', title: 'The idea', body: ['Абзац.', 'Ещё абзац.'], media: null }
```

Главу можно удалить, добавить или переименовать. Глава с пустым `body`
не рендерится, поэтому незаполненные разделы не оставляют дыр в вёрстке.

### Изображения

Если `src: null`, `MediaFrame` рисует аккуратный плейсхолдер нужных пропорций.
Layout не ломается, можно спокойно собирать сайт до появления финальных картинок.

## Дизайн-система

Все цвета, шрифты, размеры, отступы и тайминги — в `styles/tokens.css`.
Это единственное место, где их нужно менять.

- `styles/tokens.css` — токены
- `styles/typography.css` — типографическая шкала (`.t-display`, `.t-h2`, `.t-meta` …)
- `styles/globals.css` — ресет, focus-состояния, утилиты

Сетка: 12 колонок, max-width 1560px, шаг 8px. Компонент `Container` с пропом
`grid` включает сетку; дочерние элементы позиционируются через `grid-column`.
На ширине < 768px сетка автоматически схлопывается в одну колонку.

Шрифты (Inter Tight + JetBrains Mono) ставятся через npm и раздаются с вашего
домена — никаких запросов к внешним CDN.

## 3D: как настроить куб

### Заменить букву

`components/three/assets/letterA.ts` — единственный файл с формой буквы.
Вставьте свой SVG в поле `svg`. Требования:

- только элементы `<path>` с атрибутом `d` (переведите текст и фигуры в контуры);
- координаты SVG (ось Y вниз) переворачиваются автоматически — рисуйте как обычно;
- размер viewBox не важен: геометрия центрируется и масштабируется сама;
- перекрывающиеся контуры допустимы, при экструзии они сливаются.

Там же настраиваются `depth` (глубина), `bevel` (фаска) и `height` (высота в
единицах сцены; ребро куба = 2.2).

### Настроить движение

`components/three/GlassCube.tsx`, блок «ПАРАМЕТРЫ ВРАЩЕНИЯ» вверху файла:

| Параметр | Что делает |
|---|---|
| `MAX_YAW` | предел доворота влево/вправо (сейчас ~22°) |
| `MAX_PITCH` | предел наклона вверх/вниз (сейчас ~13°) |
| `SMOOTH_TIME` | инертность: больше — тяжелее и медленнее |
| `IDLE_AFTER` | через сколько секунд покоя куб возвращается |
| `DRIFT_AMPLITUDE` / `DRIFT_PERIOD` | медленный дрейф в покое |
| `BASE_YAW` / `BASE_PITCH` | базовый разворот в три четверти |

Куб не вращается бесконечно: поворот всегда ограничен и всегда стремится
к базовому положению.

### Материалы и свет

- Стекло куба — `MeshTransmissionMaterial` в `GlassCube.tsx`.
- Свет — `components/three/StudioEnv.tsx`: софтбоксы на `Lightformer`,
  без HDRI-файлов. Окружение запекается один раз (`frames={1}`).

### Качество и производительность

`hooks/useDeviceTier.ts` задаёт три уровня:

| Уровень | Условие | Что меняется |
|---|---|---|
| `high` | десктоп, ≥ 8 ядер | samples 6, resolution 512, backside, DPR до 1.5 |
| `mid` | остальные с WebGL | samples 3, resolution 256, без backside, DPR 1 |
| `low` | нет WebGL, ≤ 2 ядра или ≤ 2 ГБ | канвас не монтируется, показывается `Fallback3D` |

Канвас переходит в `frameloop: 'never'`, когда куб вне экрана или вкладка
неактивна. При `prefers-reduced-motion` куб застывает в статичном развороте,
а рендер переключается в режим по запросу.

При потере WebGL-контекста сцена отключается и на её место встаёт статичный
`Fallback3D` — пустого прямоугольника не появится.

## Домен

Адрес сайта берётся из переменной окружения:

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен
```

Без неё подставляется `https://set-your-domain.invalid`. Зона
`.invalid` зарезервирована стандартом и никому не принадлежит,
поэтому выкатить плейсхолдер в продакшен незаметно невозможно.
Файл-образец — `.env.example`.

## Финализация (SEO / деплой)

### Что готово

| Проверка | Статус |
|---|---|
| `title` / `description` / canonical | на каждой странице, из `content/profile.ts` и данных проекта |
| Open Graph + Twitter Card | своя карточка для главной и для каждого проекта (`/og-image.png`, 1200×630) |
| JSON-LD (`schema.org/Person`) | в `<head>`, собирается из `content/profile.ts` и `content/contact.ts` — `sameAs` появится сам, как только заполните реальные ссылки |
| `sitemap.xml` / `robots.txt` | генерируются из `publishedProjects` — добавили проект, он появился сам |
| favicon (`icon.svg`) и apple-touch-icon | оба — тот же знак, что в 3D-сцене |
| Контраст текста | `--c-gray-500` (метаданные, лейблы) проверен по WCAG: было 3.2:1, стало 5.19:1 — посчитано, не на глаз |
| Обработка рантайм-ошибок | `app/global-error.tsx` — если что-то в приложении упадёт, экран не останется белым |
| 404 | реальный статус-код (не soft-404), проверено на production-сборке |

### Перед первым деплоем

1. Задайте `NEXT_PUBLIC_SITE_URL` в переменных окружения хостинга — без неё canonical, OG и sitemap указывают на заведомо нерабочий `set-your-domain.invalid` (это осознанное решение, не забытый плейсхолдер: см. `lib/site.ts`).
2. Замените `public/og-image.png`, если появится собственный визуальный стиль карточки — сейчас это программно сгенерированный вариант в стилистике сайта (typography + линия + силуэт куба с A).
3. Проверьте `content/profile.ts` → `seo.title` / `seo.description` — сейчас они нейтральные, без выдуманных фактов.

### Деплой на Vercel

```
1. Подключите репозиторий на vercel.com
2. Settings → Environment Variables → NEXT_PUBLIC_SITE_URL = https://ваш-домен
3. Deploy — сборка и настройка происходят автоматически
```

Переменных окружения, кроме `NEXT_PUBLIC_SITE_URL`, проекту не требуется.

## SEO — финальный технический слой

Собрано без сторонних сервисов, через встроенные конвенции Next.js.

| Что | Файл | Как работает |
|---|---|---|
| OG-картинка сайта | `app/opengraph-image.tsx` | генерируется на лету, монохром, имя + роль |
| OG-картинка проекта | `app/projects/[slug]/opengraph-image.tsx` | своя карточка на каждый проект — название и категория берутся из `content/projects.ts` |
| Apple touch icon | `app/apple-icon.tsx` | тот же знак A, что в `icon.svg`, отдельным PNG (iOS не читает SVG-иконки) |
| Манифест | `app/manifest.ts` | имя и описание из `content/profile.ts` |
| Структурированные данные | `components/seo/PersonJsonLd.tsx` | schema.org/Person — только имя, роль и домен. `sameAs` подставляется из `content/contact.ts` **только** если там появится реальная ссылка. Пока домен не задан (`NEXT_PUBLIC_SITE_URL`), блок не рендерится вовсе — подставлять `.invalid`-домен в структурированные данные было бы такой же выдумкой, как и любой другой факт |
| sitemap / robots | `app/sitemap.ts`, `app/robots.ts` | собираются из `publishedProjects` — `published: false` убирает проект отовсюду |

Общий генератор карточек — `lib/og-image.tsx`, используется и главной, и проектами: один источник вёрстки для всех OG-изображений.

## SEO — финальный набор

| Файл | Что даёт |
|---|---|
| `app/opengraph-image.tsx` | OG-карточка главной, генерируется как PNG 1200×630 |
| `app/twitter-image.tsx` | то же для Twitter Card |
| `app/projects/[slug]/opengraph-image.tsx` | своя карточка под каждый проект — категория + название |
| `app/icon.svg` | favicon |
| `app/apple-icon.tsx` | PNG-иконка 180×180 для iOS-домашнего экрана (SVG туда не годится) |
| `app/manifest.ts` | web manifest |
| `app/sitemap.ts` | XML sitemap, собирается из `publishedProjects` |
| `app/robots.ts` | robots.txt со ссылкой на sitemap |

Все карточки рисуются кодом (`lib/og.tsx`) — не изображениями. Общий рендерер задаёт вид: контур с буквой A, категория, название, подпись. Добавили проект в `content/projects.ts` — у него уже есть корректная OG-карточка, ничего вручную создавать не нужно.

Без явного файла шрифта: `next/og` поддерживает только TTF/OTF/WOFF, а в проекте только WOFF2 (Inter Tight). Рендерер использует системный fallback — для превью-карточки, которая не является частью самого сайта, конвертация шрифта ради этого была бы избыточной.

## Деплой

**Vercel** (рекомендуется, нативная поддержка Next.js):

1. Подключите репозиторий на vercel.com.
2. Задайте переменную окружения `NEXT_PUBLIC_SITE_URL` = ваш домен.
3. Deploy — настройка сборки не требуется (`next build` определяется автоматически).

Без переменной окружения canonical, sitemap и Open Graph будут ссылаться на заведомо нерабочий `https://set-your-domain.invalid` — сайт при этом продолжит работать, но метаданные будут показывать placeholder-адрес.

После первого деплоя стоит проверить:
- `/sitemap.xml` и `/robots.txt` отдают реальный домен;
- ссылка на сайт в Twitter/Slack/Telegram показывает OG-карточку;
- `/projects/nope` (любой несуществующий slug) отдаёт 404, а не 200.

## Админка фото (/admin)

Отдельная защищённая паролем страница для добавления/удаления фото
в галереях четырёх кейсов (Dream Life, Ascend Club, NutriSnap,
Martinez) — без правки кода и без git.

**Важно понимать, как это устроено:** сайт остаётся полностью
статическим. Фото, загруженное через `/admin`, не появляется на
сайте мгновенно — оно сохраняется, и сайт пересобирается (5–10
секунд), после чего фото на месте. Это осознанный компромисс
(вы сами его выбрали): без него пришлось бы превращать статические
страницы в динамические ради одной админ-функции.

Основная композиция сайта (обложки проектов, подборка на HOME) —
по-прежнему ручная редакторская работа в `content/projects.ts`.
Через `/admin` управляется только `gallery` — дополнительные кадры
внутри страницы кейса, поле, изначально для этого и предназначенное.

### Настройка (один раз, в панели Vercel)

Ничего из этого нельзя сделать через код — только руками в
интерфейсе Vercel:

1. **Пароль.** Vercel → проект → Settings → Environment Variables →
   добавить `ADMIN_PASSWORD` с любым значением. Без него `/admin`
   не открыта всем — она просто не открывается никому, включая вас.
2. **Vercel Blob** (хранилище файлов). Storage → Create Database →
   Blob → подключить к проекту. Переменная `BLOB_READ_WRITE_TOKEN`
   подставится автоматически.
3. **Redis** (список фото на проект; Vercel KV как отдельный продукт
   устарел, актуальный путь — интеграция с Upstash). Storage →
   Create Database → в Marketplace найти Redis (Upstash) → подключить.
   `KV_REST_API_URL` и `KV_REST_API_TOKEN` подставятся автоматически.
4. **Deploy Hook** (запуск пересборки после изменений). Settings →
   Git → Deploy Hooks → Create Hook → любое имя, ветка `main` →
   скопировать URL в переменную `VERCEL_DEPLOY_HOOK_URL`.
5. Redeploy проекта, чтобы новые переменные окружения применились.

Без какого-то одного из пунктов 2–4 сайт и `npm run build`
продолжают работать как обычно — просто `/admin` покажет, чего
не хватает (жёлтый блок вверху страницы), и соответствующая
функция не сработает, вместо того чтобы упасть с ошибкой.

### Как этим пользоваться

Откройте `/admin`, введите пароль. На странице — четыре проекта,
у каждого текущие добавленные фото и форма загрузки. Загрузили —
через 5–10 секунд обновите сайт, фото в галерее кейса. Удалили —
то же самое, плюс файл физически стирается из Blob.

### Локальная разработка

`npm run dev` без единой из переменных `ADMIN_PASSWORD` /
`BLOB_READ_WRITE_TOKEN` / `KV_REST_API_URL` работает точно как
раньше — `/admin` просто вернёт на страницу логина и ничего не
даст сделать. Чтобы проверить админку локально, скопируйте
значения из Vercel (Settings → Environment Variables → Show) в
`.env.local`.
